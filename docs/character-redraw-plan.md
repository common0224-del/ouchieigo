## 3. 制作の順序と品質ゲート（現段階では実行しない）

1. 所有者指定の順に `word-target-girl` → `action-get-boy` → `action-bring-boy` → `action-throw-boy` → `action-put-girl` → `action-get-girl` → `action-bring-girl` → `action-throw-girl` を1枚ずつ制作・承認する。承認前は公開用画像を差し替えない。参照画像は `docs/characters/`、Action Match の人物・小道具・絵のタッチの基準は承認済み `action-put-boy-v4` とする。以後の画像は等幅コマとし、画像内の区切り線・矢印は描かず、アプリ側の三角用に境界の余白を設ける。
2. 元絵は `source-images/` に保管し、**透明背景を生成に要求せず、人物・道具に使わない単色緑 `#00FF00` 背景**で生成する。背景色に実測の揺れがあれば輪郭の緑かぶりを点検する。別キャラクターの顔、髪、服を混ぜず、動作の前後と道具を見て理解できる構図にする。
3. `python3 scripts/chroma-key-green.py 元画像.png 透過画像.png` で緑を透明化し、拡大して髪・指・服・道具の輪郭、薄い緑の縁、意図しない穴を目視で確認する。必要なら元絵／切り抜きを修正し、緑が残る候補を採用しない。
4. `scripts/optimize-images.sh` で公開用 WebP（画質84、Action Match 長辺800px以下、Item Match 長辺512px以下）へ変換し、`node tests/check-image-alpha.mjs 候補.webp` で四隅と透明領域を確認する。背景5枚はこの透過検査の除外対象。変換前後・全画像合計の容量も報告し、配布用本体の10MB目安を守る。
5. **重要な手・動作・対象物・相手の顔は各画像の上側80%（画像高さを H として y ≤ 0.8H）に収める。** 下側20%がカード表示や端末サイズの違いで見切れても「put / get / bring / throw」が伝わるか確認する。余白や足は下側でもよい。なお現行 CSS の `.action-card` は `overflow:hidden`、画像は `object-fit:contain` なので、常に画像の下20%を機械的に切っているわけではない。端末表示での可読性を守る**制作上の安全余白**とする。
6. 新旧を並べ、カード内での実寸と 375×667／390×844／430×932 の画面を確認する。髪・顔・服・コマ幅・境界の余白・道具のタッチ、およびアプリ側の三角との重なりを比較し、承認を受けてから `index.html` の参照を置き換える。`zsh tests/run-all.zsh` を実行し、Action Match とレイアウトを重点確認する。公開反映は所有者の確認後に行う。

## 4. 参照されていない公開用画像

**該当なし。** 公開用画像の範囲をリポジトリ直下の `.webp` 60枚とし、各ファイル名が `index.html` の HTML・CSS・JavaScript のいずれかにあるか照合した結果、60枚すべてに参照があった。`bathroom-stage-v4.jpg.webp` は現在の洗面所の背景画像ではないが、場所選択カードの CSS `background-image` に使われている。`source-images/`・`private-prototypes/`・`docs/characters/` の保存・比較用画像は、この「公開用画像」の対象外。静的参照の有無を確認した結果であり、各画像がプレイ中に必ず表示されるという意味ではない。
